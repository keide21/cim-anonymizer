# Обезличивание модели CIM

Скрипт `anonymize_cim.py` обрабатывает экспорт CIM RDF/XML. Он записывает обезличенный XML рядом с исходником или по указанному пути. Исходник открывается для чтения. При ошибке скрипт сохраняет прежний выходной файл, если он уже существовал.

## Запуск в Windows

Распакуйте архив в рабочую папку. Нужен Python 3.11 или новее. Прогон проверен на Python 3.12. Выполните в PowerShell:

```powershell
py -3.12 -m venv .venv312
.\.venv312\Scripts\python.exe -m pip install -r requirements.txt
.\.venv312\Scripts\python.exe -X utf8 .\anonymize_cim.py .\input.xml .\input-anonymized.xml --key-file .\cim.key --coordinates --ref-cache-size 800000 --fast-diagrams --diagram-workers 4
```

При первом запуске скрипт создаёт ключ. Храните его отдельно от выгрузки. Используйте тот же ключ, чтобы получить те же псевдонимы. Флаг `--coordinates` обнуляет числовые координаты и их высоту в полях модели. Если флаг пропустить, географические координаты сохраняются. Координаты размещения условных знаков на однолинейных схемах относятся к оформлению этих схем.

Скрипт читает XML по записям и записывает их в исходном порядке во временный файл рядом с выходным. Для прогона нужен диск под выходной XML. Проверка дополнительно использует временный индекс SQLite.

Для выгрузки около 1 ГБ используйте `--diagram-workers 4 --fast-diagrams --ref-cache-size 800000`. Четыре отдельных процесса обрабатывают вложенные схемы, а уровень сжатия 1 сокращает время упаковки. При ограниченной памяти начните с настроек по умолчанию, одного процесса и кэша на 200 000 записей. Меньший кэш может потребовать пересчёта части идентификаторов.

Скрипт удерживает до 16 записей в очереди и начинает выгружать готовые результаты при 32 МиБ входных строк Base64. Отдельный пакет схем может содержать до 16 384 файлов и до 256 МиБ суммарных данных при распаковке с учётом вложенных пакетов. Слишком большой или неоднозначный пакет останавливает обработку с указанием записи.

В итоговом JSON поле `seconds` показывает длительность этапов, а `ref_cache` — попадания, промахи и заполнение кэша. Для перевода синтетических подписей передайте `--config language.example.json`. Этот файл содержит несколько примеров перевода. Для другого языка подготовьте собственный словарь.

## Проверка результата

```powershell
.\.venv312\Scripts\python.exe -X utf8 anonymize_cim.py input.xml input-anonymized.xml --key-file cim.key --coordinates --verify
```

Используйте те же настройки обезличивания, уровень сжатия и словарь, что и при обработке. Проверка заново вычисляет ожидаемые значения, сравнивает записи по порядку и сверяет разрешение RDF-ссылок до и после замены. Она проверяет уникальность RDF-идентификаторов и полей `IdentifiedObject.name`. Ссылки без определения в обоих файлах учитываются отдельно.

В `verification-report.json` приведены результаты полного запуска на выгрузке объёмом 965 687 909 байт. Независимая проверка сверяет верхний уровень CIM с ранее проверенной выгрузкой, а содержимое вложенных схем — с исходником. Для схем проверяются размеры, числовые значения, ссылки по UUID, формулы с переименованными операндами и синтаксис встроенных C#-скриптов.

## Правила замены

| Данные | Правило |
| --- | --- |
| ФИО физлиц и сотрудников | Фамилия, имя и отчество берутся из синтетического справочника. Поля имени, email и улицы внутри записи физлица используют один профиль. У поля наименования объекта есть суффикс для уникальности. |
| Абоненты | Категория читается из `Customer.kind` или связанного справочника `Customer.OMSKind`. При отсутствии категории используется распознаваемый формат ФИО. Исходные связи с категориями сохраняются. |
| Организации и оборудование | Наименования строятся из прилагательных от овощей и фруктов. Для известных классов добавляется обозначение оборудования. При замене цифровых номеров сохраняется количество знаков. |
| Идентификаторы и ссылки | UUID псевдонимизируются взаимно однозначно. Один и тот же RDF-идентификатор заменяется согласованно во всех ссылках. Ссылки на значения схемы сохраняются. |
| Технические параметры | Сохраняются классы XML, топология, параметры напряжения и нагрузки, записи региональных справочников и ссылки на них. Названия регионов заменяются. |
| Связанные имена | Если `Name.name` повторяет имя связанного объекта, оба поля получают одну замену. |
| Расчётные формулы | Переменные с объявлениями получают одинаковые псевдонимы в объявлении и формуле. Операции и числовые константы сохраняются. |
| Текст и вложения | Комментарии и свободный текст заменяются. В известных шаблонах сохраняются параметры подстановки. В схемах сохраняются размеры, числовые значения и технические поля `Field`. UUID заменяются по тем же правилам, что и в основной модели. Имена операндов меняются согласованно в формулах и объявлениях. Подписи, имена пользователей и списки имён обезличиваются. Растровые изображения заменяются заглушками, звук — тишиной. |

В исходной выгрузке 55 уникальных кириллических имён в формулах не совпали с объявлениями операндов этих формул. Для них скрипт создаёт стабильные псевдонимы. Проверка охватывает XML и связи с операндами. Исполнение расчётов в CIM-приложении остаётся за её рамками.

Правила настроены на поля предоставленного экспорта и распространённые имена полей CIM. Новый профиль CIM может использовать другие свойства для персональных данных, особенно для числовых значений и вложений. Перед обработкой такого профиля проверьте его список полей и при необходимости дополните правила. Поддерживается обычный экспорт с корнем `rdf:RDF`. Объявления DTD и `xml:base` отклоняются.
